# 逻辑关联迁移

`20261027_drop_foreign_keys.sql` 移除 `news_app` 中现有的 9 个物理外键；
关联字段、主键、唯一约束和普通索引均保留。该脚本针对迁移前表结构编写，
不可在已迁移的数据库上重复执行。

物理外键移除后，数据库不再自动校验关联，也不会自动执行原来的级联删除、
级联更新或限制删除。今后实现写入和删除功能时，业务层必须在事务中检查
目标记录，并按需求处理收藏、历史、相关新闻、令牌等关联记录。现有令牌
鉴权使用显式连接查询用户；当前项目尚未实现通用的关联清理机制。

`20261027_restore_foreign_keys.sql` 记录原有外键和级联规则，供需要恢复时
使用。如果迁移后出现孤儿记录，恢复前须先处理，否则恢复会失败。
MySQL 的 `ALTER TABLE` 会隐式提交，多条语句不是一个原子事务；执行前应
备份数据库并核对目标库、约束名称和关联数据。
