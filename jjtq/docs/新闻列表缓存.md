# 新闻列表缓存

`GET /api/news/list` 使用缓存旁路策略。Redis 客户端复用应用生命周期内的连接池；
分类列表、新闻详情和用户数据不使用该缓存。查询参数和响应格式保持不变。

## 配置 Redis

安装项目依赖后，在 `jjtq/backend/.env` 添加 Redis 地址，示例：

```dotenv
REDIS_URL=redis://:你的密码@localhost:6379/1
```

`/1` 是 Redis 数据库编号。地址支持 Redis 标准 URL，用户名和密码包含 `@`、
`:`、`/` 等特殊字符时应先进行 URL 编码。密码放在本地 `.env` 中，不应提交。
未设置 `REDIS_URL` 时默认使用 `redis://localhost:6379/1`，适合无需认证的本机
Redis。应用启动时检查地址解析后的数据库编号，非 1 的配置会被拒绝；URL 的
`db` 查询参数优先于路径编号，不能通过查询参数改用数据库 0。

修改 `.env` 后重启后端。Redis 服务暂不可用、认证失败或读取超时时，新闻列表
回退到数据库查询；缓存写入失败也不影响本次响应。缓存不可用时会记录警告，
应检查连接地址、密码及 Redis 状态。连接和操作超时均为 0.3 秒，不进行重试。

## 缓存键和有效期

缓存键模板和有效期常量集中在 `jjtq/backend/constants/cache.py`：

```text
jjtq:news:list:v1:{category_id或all}:{page}:{page_size}
```

同一分类、页码和每页数量共用缓存；不同参数使用不同键。`all` 表示不指定分类，
`v1` 为缓存数据格式版本。Value 是与现有接口列表字段一致的 JSON 数组。

- 非空列表缓存 600–660 秒，其中 0–60 秒为随机抖动。
- 空列表缓存 60–70 秒。空数组属于有效缓存命中，不重复查询数据库。
- 缓存内容损坏或格式不正确时，重新查询数据库并尝试覆盖。

缓存命中时直接返回列表；未命中时查询数据库，序列化后写入 Redis 并返回。
数据库查询失败仍按原有机制报错，不会写入错误缓存。

## 数据更新与时区

目前没有新闻新增、修改或删除接口，列表缓存依靠 TTL 自动过期。以后增加新闻
写接口时，应在数据库事务成功提交后使相关分类及全部分类的分页缓存失效。
列表中的浏览量可能延迟至多 660 秒更新，新闻详情仍从数据库获取并原子累加。

应用新建 MySQL 连接时将**会话**时区设为 `+08:00`，不修改数据库全局时区。
MySQL 的 `TIMESTAMP` 与数据库 `NOW()` 按会话时区显示；已有记录不需要迁移。
自定义时区的其他数据库连接不受此设置影响。应用关闭时会释放 Redis 和 MySQL
连接池；每次请求结束时仍由 `get_db` 单独关闭其数据库会话。
