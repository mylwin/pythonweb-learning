# 用户注册接口

`POST /api/user/register`

请求体为 JSON。注册和登录共用校验规则：用户名长度为 2–50 个字符，
只允许字母和数字（支持中文）；
密码长度为 6–72 个字符，允许符号，按 UTF-8 编码后不能超过 72 字节。

```json
{
  "username": "jjtq",
  "password": "123456"
}
```

注册成功时返回 HTTP 200：

```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "token": "1f0c9c3f7a2b4d8e9f6a5c1b2d3e4f50",
    "userInfo": {
      "id": 1,
      "username": "jjtq",
      "bio": "这个人很懒，什么都没留下",
      "avatar": null
    }
  }
}
```

- 密码使用 bcrypt 随机盐哈希后入库，数据库中不保存明文；登录使用原哈希验证。
- `token` 为随机生成的 32 位十六进制字符串，有效期为 7 天；服务端在
  `user_token` 表中保存 SHA-256 摘要、用户 ID 和过期时间，不保存原始令牌。
- `userInfo` 使用驼峰字段名，`bio`、`avatar` 可以为 `null`。

用户名已存在时返回 HTTP 409：

```json
{"code": 409, "message": "用户名已存在", "data": null}
```

请求体字段缺失或不合法时返回 HTTP 422，`data` 包含字段位置和中文提示，
不会返回输入值。密码长度不符合要求的示例：

```json
{"code": 422, "message": "请求参数校验失败", "data": [
  {"loc": ["body", "password"], "type": "string_too_short", "msg": "密码长度不能少于 6 个字符"}
]}
```

登录接口为 `POST /api/user/login`，请求体字段与注册一致。用户名不存在、
密码错误或存储哈希无效时，均返回 HTTP 401 和“用户不存在或密码错误”。

登录或注册后，可使用 `GET /api/user/info` 查询当前用户：

```http
Authorization: Bearer <token>
```

成功时 `data` 包含 `id`、`username`、`bio`、`nickname` 和 `avatar`，不包含
密码。令牌不存在、格式错误、过期或对应用户不存在时返回 HTTP 401。
通过数据库时间判断过期；注册或登录生成令牌时与用户操作在同一事务中提交。
启用持久化前返回的旧令牌无法验证，需要重新登录。当前登出仅清除前端状态，
已签发令牌会在到期前保持有效。

数据库事务由 `get_db` 统一提交；用户名唯一约束由数据库兜底。

后端开发约定见 `jjtq/backend/AGENTS.md`；手动请求示例见
`jjtq/backend/tests/users.http`。

运行测试：

```bash
uv run python -m unittest discover -s jjtq/backend/tests -v
```
