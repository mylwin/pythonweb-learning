# 浏览历史接口

所有接口需携带 `Authorization: Bearer <token>`；凭证缺失、无效或已过期
返回 HTTP 401。当前用户由令牌确定，不接受客户端指定用户身份或浏览时间。
接口路径与项目现有前端调用保持一致。

## 记录浏览

`POST /api/history/add`，JSON 请求体：

```json
{"newsId": 10}
```

成功响应示例：

```json
{
  "code": 200,
  "message": "记录浏览历史成功",
  "data": {"id": 1, "userId": 2, "newsId": 10, "viewTime": "2026-10-28T12:00:00"}
}
```

`newsId` 必须为正整数。新闻不存在时返回 HTTP 404，请求体缺失、参数不合法
或包含额外字段时返回 HTTP 422。浏览时间取数据库默认时间。

现有 `history` 表允许同一用户多次浏览同一新闻，每次请求记录一次浏览事件。
列表查询按新闻归并；重复、并发浏览不会导致列表中出现重复新闻。
历史记录接口不累加新闻浏览量，浏览量由现有新闻详情接口维护。

## 查询列表

`GET /api/history/list?page=1&pageSize=50`

- `page` 默认为 1，必须大于等于 1。
- `pageSize` 默认为 50（与前端本地历史显示上限一致），范围为 1–100。
- 参数不合法时返回 HTTP 422。

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [
      {
        "id": 10,
        "title": "新闻标题",
        "description": null,
        "image": null,
        "author": null,
        "publishTime": "2026-10-28T10:00:00",
        "categoryId": 1,
        "views": 3,
        "viewTime": "2026-10-28T12:00:00"
      }
    ],
    "total": 1,
    "hasMore": false
  }
}
```

列表中的 `id` 是新闻 ID，新增接口返回的 `data.id` 则是历史记录 ID。
`viewTime` 为当前用户最近浏览该新闻的时间。先按新闻归并，再分页，按最近
浏览时间倒序排列，时间相同时以该新闻最新历史记录 ID 倒序确定稳定顺序。
只查询新闻摘要，不返回正文。新闻已删除的记录不会进入列表和总数。

`total` 为当前用户浏览过且仍存在的不同新闻数；`hasMore` 表示当前页之后
是否还有新闻。无历史时返回 `list: []`、`total: 0`、`hasMore: false`；超出
页数返回空列表并保留实际总数。服务端没有自动删除旧历史的数量上限。

## 删除单条新闻的历史

`DELETE /api/history/delete/{id}`

路径参数 `id` 为新闻 ID，必须为正整数，与前端列表中的 `id` 对应。
仅删除当前用户对这条新闻的全部浏览事件；其他新闻及其他用户不受影响。
新闻或历史不存在时仍返回成功，因此重复删除也是安全的。

```json
{"code": 200, "message": "删除浏览历史成功", "data": null}
```

## 清空历史

`DELETE /api/history/clear`，无请求体。

```json
{"code": 200, "message": "清空浏览历史成功", "data": null}
```

仅清除当前登录用户的全部浏览事件，包括新闻已删除的残留记录。空历史重复
清空仍返回成功。写操作由 `get_db` 统一提交和回滚，异常时不保留部分结果。

模型与现有表结构对应，不新增物理外键、不修改数据库表结构。
手动请求示例见 `jjtq/backend/tests/history.http`。
